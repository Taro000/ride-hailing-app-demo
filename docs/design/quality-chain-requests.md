設計の連鎖は、品質チェーン（`docs/quality/`）を直さない。品質チェーンの要求を変えるべきだと設計で分かったときや、設計に要る要求が品質チェーンにないときは、品質チェーンへの要求を書く。ここには、未回答と回答済みの要求がすべてある。答えが決まった要求には、「答え:」の後に答えを書く。次の設計の実行が、それを要求に写す。そのうえで、この文書を「品質チェーンの段ごとにすること」に挙げた段に渡して、その段を再実行する。設計の段は、次の実行で `docs/quality/` の変わった所に追随し、反映された要求をここから外す。

## 要求と答え

### QCR-01 ドライバーの現在地から乗車場所までの距離は、道のりか直線か

- 状態: 未回答 · 出した段: 第 1 段階
- 影響: 低。DRV-08 は主な線の下にあり、どちらの距離でも EXT-02 は一つのつなぎ口の後ろに置ける。ドライバーは 1 人（OPF-03）で、道のりでも依頼ごとに一度求めるだけ。答えが来るまで、設計は品質チェーンの今の要求のとおりに進める
- 品質チェーンの項目: FR-19、FR-20、FR-32、QR-32 · 品質チェーンの段: 2
- 由来の項目: DRV-08 · 依存する項目: DEC-24、DRV-08
- 課題: FR-19、FR-20、FR-32 は、ドライバーの現在地から乗車場所までの距離が道のりか直線かを述べていない（品質チェーンの第 2 段階と第 3 段階も未解決の点に挙げている）。道のりなら、依頼を届ける相手を決めるたびに EXT-02 に道を求めることになり、DRV-08 の規則と EXT-02 とのつなぎ方が変わる
- 直し方の案: FR-19 と FR-32 に、条件の距離が道のりか直線かを書き、FR-20 が示す距離も同じものにする。QR-32 の失敗のシナリオもそれに合わせる

答え: —

### QCR-02 乗客とドライバーは、待つ間、迎車中、乗車中にアプリを画面に出したままにする

- 状態: 回答済み（設計の第 1 段階の質問 2） · 出した段: 第 1 段階
- 影響: 高。主な設計を動かす要求の DRV-04 と DRV-03 の環境が変わる。設計の第 1 段階の質問 2 で尋ね、答えを受けた
- 品質チェーンの項目: CON-05、DIN-04、NFR-07、NFR-19、QR-06、QR-19 · 品質チェーンの段: 1
- 由来の項目: DRV-03、DRV-04、DRV-14 · 依存する項目: DEC-02、DEC-06、DEC-07、DEC-21、DRV-03、DRV-04、DRV-14、DRV-26、ELM-01
- 課題: DIN-04（iOS の Safari で使う Web アプリ）のもとでは、アプリが前に出ていない間（ほかのアプリを開いている、画面を消している）、端末は位置を送らず、ページの処理も止まり、知らせはホーム画面に加えた Web アプリでしか届かない（設計の第 1 段階の推定で、第 2 段階が実機で確かめる）。QR-19 と NFR-19（現在地の新しさ）、QR-06 と NFR-07（相手への速い表示）、FR-10、FR-19、FR-24、FR-26 は、その間の位置と画面に頼る。DIN-04 を保つなら、利用者ができることが限られる
- 直し方の案: 乗客とドライバーが、迎車を待つ間、迎車中、乗車中にアプリを画面に出したままにすることを、共有する事実（制約）と、CUJ-02、CUJ-03、CUJ-06、CUJ-07、CUJ-09 の利用時の品質要求の利用状況に加える。NFR-19 と NFR-07 は、アプリが前に出ていない間をどう数えるかをそれに合わせる

答え: DIN-04 を保つ。乗客とドライバーは、迎車を待つ間、迎車中、乗車中にアプリを画面に出したままにし、設計は画面を消さずに保つこと、戻ったときに今の状態に合わせること、ホーム画面に加えた Web アプリの知らせで支える。この条件を QCR-02 で品質チェーンに記録する。（下書きどおり。試行の模擬回答）

### QCR-03 ドライバーは受付をしている間もアプリを画面に出したままにする

- 状態: 回答済み（設計の第 2 段階の質問 2） · 出した段: 第 2 段階
- 影響: 高。主な設計を動かす要求の DRV-04 と DRV-03 の環境が変わり、DEC-07 が送る場面も変わる。設計の第 2 段階の質問 2 で尋ね、答えを受けた
- 品質チェーンの項目: CON-05、NFR-19、QIU-15〜QIU-17、QIU-20、QR-19、SLI-10 · 品質チェーンの段: 1
- 由来の項目: DEC-07、DRV-04 · 依存する項目: DEC-07、ELM-01、TC-18
- 課題: QCR-02 の答え（設計の第 1 段階の質問 2）は、乗客とドライバーが迎車を待つ間、迎車中、乗車中にアプリを画面に出したままにするとしたが、ドライバーが受付をしている間（CUJ-06、CUJ-09）を挙げていない。一方で QCR-02 の直し方の案は、その条件を CUJ-06 と CUJ-09 の利用状況にも加えるとしている。QR-19 と NFR-19（SLI-10）は受付をしているドライバーの現在地も数え、FR-19 はその現在地で依頼を届けるかを決め、QR-06 はドライバーの一覧に依頼を示す速さを求める。iOS の Safari の Web アプリ（DIN-04）は、前に出ていない間は位置を送れず、一覧も変化を受けられない
- 直し方の案: QCR-02 の条件に、ドライバーが受付をしている間もアプリを画面に出したままにすることを加え、共有する事実（制約）と、CUJ-06 と CUJ-09 の利用時の品質要求（QIU-15、QIU-16、QIU-17、QIU-20）の利用状況に書く。NFR-19 と SLI-10 の数え方は、それに合わせる

答え: 含む。ドライバーは受付をしている間もアプリを画面に出したままにし、QCR-03 のとおり品質チェーンに記録する（下書きどおり。試行の模擬回答）

## 品質チェーンの段ごとにすること

下の段に、この文書を渡して再実行する。その段は答えを反映し、答えのない要求はあなたと決める。品質チェーンの後の段は、その変更に自分の再実行で追随する。

### 第 1 段階（`cuj-to-quality-in-use`）

- CON-05、DIN-04: QCR-02 乗客とドライバーは、待つ間、迎車中、乗車中にアプリを画面に出したままにする（回答済み）
- CON-05、QIU-15〜QIU-17、QIU-20: QCR-03 ドライバーは受付をしている間もアプリを画面に出したままにする（回答済み）

### 第 2 段階（`quality-in-use-to-functional-requirements`）

- FR-19、FR-20、FR-32: QCR-01 ドライバーの現在地から乗車場所までの距離は、道のりか直線か（未回答）
