## 概要
第 4 段階の ELM-02（担当者とエンジニアの Web アプリ）の 3 回目のレビューで、前のレビュー（fce51d7）からの差分のレビュー。設計を書いた会話とは別の文脈で、成果物だけを読んだ。範囲は、この段階が中の FND-52 と軽微な FND-53、FND-54 を受け入れて変えた MOD-01、MOD-02 と ELM-02 の報告（60a7c85）。前のレビューの後に docs/quality/ と前の段階の項目は変わっていない。

指摘はない（重大 0、中 0、軽微 0）。

FND-52 は案と違う直し方で受け入れられたが、案より広く閉じている。MOD-01 は答えを待っている変える要求がある操作を kept() で捨てずにその状態のまま返して中止せず、MOD-02 は開き直した画面でその Outcome を待ち、読み込み中に Outcome が来れば一覧を読み直す。そのため、このタブの要求が ELM-03 に届いて返金を書く前に読んだ一覧で、新しい返金を受け付けることがない。案の「unanswered として返す」では、一覧が要求より先に読まれ、一覧の答えより前に操作が定まる場面が残っていた。最初の要求の答えを待つ間に画面を離れて戻る場面を、要求が一覧より先か後に答える場合、待つ間の 429 と 401、タイムアウトの後の間を置く、タブの読み直し、複製、ほかのタブのアカウントの変化で通し、二重の返金になる道は見つからなかった。FND-53 で判断表 C は Outcome と evidence のどの組にも一行が当たり、FND-54 で MOD-01 の functions と割り当てが合う。値は変わらず、加わった振る舞いは新しい待ちも値も持たない。

残るリスクは前のレビューのときと同じで、確かめの答えから要求を出すまでのタブの間の幅（第 3 段階宛ての軽微な FND-50）と、何も配備しない（TC-09）ため確かめていないブラウザの振る舞いと、まだ決まっていない ELM-03 の答えの期限（未解決の点）。質問はなく、仮定は書いておらず、品質チェーンへの要求は出しても答えてもいない。
