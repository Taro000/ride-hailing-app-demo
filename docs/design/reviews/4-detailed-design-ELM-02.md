## 概要
第 4 段階の ELM-02（担当者とエンジニアの Web アプリ）の 2 回目のレビューで、前のレビュー（63ad346）からの差分のレビュー。設計を書いた会話とは別の文脈で、成果物だけを読んだ。範囲は、第 3 段階が FND-45 と FND-36〜FND-41 を受け入れて変えた入力（890bb9f）と、この段階が FND-43、FND-44、FND-46〜FND-48 を受け入れて変えた ELM-02 の項目（0347322）。この報告を変えた design-review の最後のコミットは bf2bdf8 だが、それは第 3 段階のレビューがこの報告の生成する表を書き直しただけで、ELM-02 のレビューではない。そこを基にすると 890bb9f の変更が範囲から落ちるので、ELM-02 の前のレビューの 63ad346 を基にした。

指摘は 3 件で、中 1 件と軽微 2 件。どれも `high-level-design-to-detailed-design` 宛て。

- FND-52（中）: FND-46 を受けて MOD-01 の evidence を変える要求の結末で上げるとしたため、最初の変える要求の答えを待つ返金の操作は evidence が notDone のままで、kept() はそれを捨てる。MOD-02 は送っている間に画面を離れても操作が送られ続け、戻ると kept() の残した操作を待つとするが、書かれたとおりなら戻った画面は残した操作がないとして新しい返金を受け付け、要求が返金を書く前に一覧が答えれば、一度だけ認めた返金が二度済みうる（QR-45、DRV-32）。
- 軽微: MOD-02 の判断表 C に、送る前の確かめが 503 か 4xx で答えた failed の行がない（FND-53）。割り当ての FR-50 の 1 が、FR-50 を functions に持たない MOD-01 を挙げる（FND-54）。

主なリスクは、FND-44 と FND-46 を受けた変更そのものが、答えを失った返金を同じキーで一度だけ行う約束に、開き直した画面という新しい穴を開けたこと（FND-52）。タブをまたぐアカウントの変化は送る前の確かめで閉じられ、残るのは確かめの答えから要求を出すまでの幅だけで、この段階が第 3 段階に出した軽微な FND-50 にある。サインインの前の操作、401 の分け方、処理されなかった返金の 503 とやり直し、タブの保存の項目と版、タブの間の知らせ、値の計算は、確かめたかぎり成り立つ。質問はなく、品質チェーンへの要求は出しても答えてもいない。
