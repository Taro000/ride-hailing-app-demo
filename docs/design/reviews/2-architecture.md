### A3 四つの問い
使い道に合うか: 前のレビューの FND-09 は閉じた。想定の本番のデモの回の外は日々の処理だけが動き、それが動かないか終えないことを、ELM-03 を通らないアラートがメールで知らせるため、DRV-24 の環境（デモの回の後の N_trace_retention_days）で、FR-51 の変換と鍵を捨てること（DRV-21）、EXT-01 との照合、NFR-39 と NFR-46 の確かめが止まったまま誰も気づかないことはなくなった。日々の処理が動いて見つけた異常（NFR-39、NFR-46）は、回の間と同じく ELM-03 が ELM-07 と一覧で知らせる（変わっていない）。合う。

寿命と計画された変更に耐えるか: 将来の変更は設計の与件にない。アラートは Cloud Monitoring の条件の決まり（利用者が定めたログの指標を見られるのは最近 25 時間）に頼るが、それが変わっても変えるのはアラートの設定だけ。技術的負債はない。耐える。

このチームが期限と予算で作って動かせ、費用に見合うか: 作るものに加わるのは、日々の処理を終えた記録と、想定の本番のアラートの設定だけ。インスタンスの時間は回の間の 3〜12 時間のままで、費用の式に P_monitoring_month が加わった。式は Secret Manager と同じく Cloud Logging の項を持たないが、量は小さく、何も配備しない（TC-09）ため判断を変えない。収まり、見合う。

作る人、使う人、保守する人に分かりやすいか: 回の外に何が誰に知らせるかの書き方は、DEC-20、ELM-08、DAS-05、CUJ-10 と DRV-24 の行、配置の表でそろい、前のレビューが挙げた食い違いはなくなった。外部との関係のメールの線は配車サービス（ELM-01〜ELM-04）から引かれるが、送るのが ELM-08 のアラートであることは注にある。分かりにくいのは脅威のモデルで、外からの生存確認からアラートへの点線だけが、信頼の境界を越えるのに表にない（FND-10）。
