## 概要
第 3 段階の二度目のレビューで、前の全体のレビュー（b4918ae）からの差分のレビュー。第 3 段階は前のレビューの中の指摘 FND-22〜FND-25 と軽微の指摘 FND-26〜FND-33 をすべて受け入れて項目を変えた（9bddc44）。このレビューは、その変わった項目と、それにつながる項目と報告の節を見た。設計を書いた会話とは別の文脈で、成果物だけを読んだ。指摘は 5 件で、どれも軽微で、どれも `architecture-to-high-level-design` 宛て。尋ねた点が一つあり、答えを当てた。

- 決めたこと 1: 品質チェーンの QAS-54（相手の画面に示した時刻を記録する FR-53 を今期作る）は、第 3 段階がその記録の上に流れの後の Web Push（IFC-11、IFC-21、DEC-46）を決めたことで、覆ればやり直す項目が DRV-03、DRV-26、IFC-10、DAT-20、IFC-11、IFC-21、DEC-46 に広がり、影響の広さが高になった（E3）。尋ねて、成り立つ（作る）と答えを受けたので、どの設計の項目も変わらない。答えは品質チェーンへの要求 QCR-08（回答済み、影響は高）が品質チェーンの第 2 段階に運ぶ。
- FND-36: 受けたインスタンスが止まった後の送り直しで行った取り消しや許諾について、SLI-14 の区間をどの要求を受けた時刻から始めるかが IFC-10 と DAT-20 になく、書かれたとおりに作ると止まって遅れた 10 秒あまりが数えから消える。
- FND-37: 外部を呼ぶ操作のキーの answerDueAt は予算の和の 8.8 秒で余裕がなく、取引が予算を超えただけのインスタンスの答えはその後になり、その間に届いた送り直しが押さえを 503 HOLD_UNCONFIRMED と答えて置き換える。
- 軽微: 流れの後の Web Push を決めた IFC-11、IFC-21、DEC-46 が、頼る QAS-54 と QAS-25 を前提に挙げていない（FND-38）。DEC-42 の Idempotent-Replayed のヘッダーが DEC-44 に加えた名付けの決まりに合わない（FND-39）。報告の DRV-01 の流れが、乗車の開始と到着の確認の端末のタイムアウトを 10 秒と描く（FND-40）。

前のレビューの中の指摘は、どれも項目で閉じている。受けたインスタンスが答える前に止まっても、外部を呼ばない操作は結果とキーと答えを一つの取引で書くため送り直しが初めから行って二重にならず、外部を呼ぶ操作は answerDueAt の後の送り直しが試みの状態から答え、押さえ中のまま残った依頼は期限の処理が受け付けなかったとする。日々の処理は止まったとみなす時刻を過ぎた実行を取り直す。境界の SLI は X-Resend で答えを受ける前の送り直しだけを一つの操作にまとめ、規則が述べていない数え方は第 3 段階が QCR-07 で品質チェーンに確かめている。乗る場所を決め始めた時刻と評価を始めたことは ELM-03 に届き、担当者はアカウントとドライバーを探して読める。予算は計算し直して報告と合い（流れの後の Web Push の道は 4.50 秒と余裕 0.50 秒）、タイムアウトの順も保たれる。重大なリスクは見つからず、主なリスクは FND-36 と FND-37 の、インスタンスが止まるか遅れたときの数え方と答え方の細部。このレビューは、決めたこと 1 の答えを運ぶ品質チェーンへの要求 QCR-08 を書いた。ほかに答えた要求はなく、反映を見つけた要求もない。
