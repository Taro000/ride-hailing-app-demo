## 概要
第 4 段階の ELM-03（配車サーバー）の最初のレビューで、全体のレビュー。設計を書いた会話とは別の文脈で、成果物だけを読んだ。指摘は 13 件で、中 5 件、軽微 8 件、どれも `high-level-design-to-detailed-design` 宛て。質問はなく、品質チェーンへの要求は出しても答えても反映を見つけてもいない。

- FND-61（中）: 乗車中の依頼に、支払い方法の変更と降りる場所の変更の押さえ直しを重ねて送れ（MOD-56 は IFC-17 の ordering を押さえごとと読む）、どちらの結果の取引も取引 A で読んだ押さえと確定額と支払い方法がまだ今のものかを確かめないので、後に済んだ方が前の結果を古い確定額か古い支払い方法の押さえで置き換え、確定額でない額を請求するか、乗客の支払い方法の変更が黙って戻る（DRV-07、FR-46 の 5、FR-54 の 5）。
- FND-62（中）: MOD-42 の判断表 B は、一回目に答えがなく同じキーで送り直した二回目が処理されなかったなら試みを処理されなかったで終える。DEC-45 と IFC-17 はそれを結果が分からないままとする。一回目が効いていれば、返金のやり直しで二度返金し、押さえは解かれず、決済は後で効きうる確定とされずに二度請求しうる（DRV-32）。
- FND-63（中）: MOD-23 の作りかけの鍵は、作り手が名前を作って中身を書く前に止まると出口がなく、その日の鍵で暗号にする項目を書くどの取引も一日止まる（DRV-01）。
- FND-64（中）: MOD-20 の判断表 A に日々の呼び出しの印（Cloud Scheduler の OIDC か共有の秘密）を確かめる行がなく、書かれたとおりでは日々の処理の呼び出しは 401 か 403 で退けられ、照合、3 年の変換と鍵を捨てること、インスタンス 0 の間の期限の処理が行われない。
- FND-65（中）: MOD-44 の照合の判断表 A に、処理されなかったとした試みの取引が EXT-01 にある組（DEC-45 が照合に任せる場合そのもの）と、済んだ試みの取引が読む期間の一覧にない組（前の日に作った押さえへの確定と解除で、ふだんにも起きる）の行がない（NFR-24、SLI-12、DRV-07）。
- 軽微: MOD-56 の判断表 C の精算の行（FND-66）、MOD-43 の登録の読み直しの requires_payment_method と確かめている間（FND-67）、MOD-51 の迎車中のドライバーの規則と MOD-52 の表の名前（FND-68）、jobs/ の import の循環（FND-69）、Cloud Run の要求の時間の上限（FND-70）、parameters にも DAS にもない値（FND-71）、MOD-39 の premises の QCR-05（FND-72）、FR-24 の割り当てと MOD-27 の functions（FND-73）。

主なリスクは、お金を一度だけ動かし記録を決済サービスと合わせる決まり（試みの一意の決まり、後で効きうる確定、照合）が、押さえ直しの重なり（FND-61）、送り直しの処理されなかった（FND-62）、照合の行の欠け（FND-65）の三つの所で破れること。もう一つは、ほかのどの機能も頼る土台のうち、日々の処理が書かれたとおりでは動かず（FND-64）、鍵が止まり方によって一日戻らない（FND-63）こと。それ以外の確定の設計（依頼の状態と許諾と取り消しと停止の重なり、冪等キー、試みの確かめと後で効きうる確定、返金の残り、期限の処理と日々の処理の取り直し、届けと示した時刻、見せる範囲、本人の確かめ、走っているかと確認コード、運賃表、値の計算）は、確かめたかぎり成り立つ。
